# Φ 的计算：决定不做，理由

## 结论

本项目**不计算 Φ**，理由不是"太难"，而是**算出来的数不构成证据**。

## 三条理由

1. **iitx / PyPhi 只吃离散 TPM。** 工作空间的广播时刻是连续激活，必须手工粗粒化成
   8–12 个二值单元。粗粒化的选择（哪些神经元、什么阈值、怎么合并）**直接决定 Φ 的值**。
   换一种粗粒化，Φ 可以差一个数量级。

2. **Φ 不是可解释的因果量。** 方案 8.3 自己写了"Φ 只作为辅助指标，不作为判决标准"。
   如果它既不是判决标准、又依赖任意粗粒化，那它在报告里就只是一行数字，
   读者无法据此更新任何信念。

3. **Phua (arXiv:2512.19155) 已经给了警告。** 他在工程系统上测 PCI-A，
   发现工作空间瓶颈下 PCI-A 反而下降——IIT 邻近代理在人工系统上方向可能是反的。
   拿 Φ 去"辅助"一个 GWT 架构，很可能得到互相矛盾的读数。

## 如果以后要做，前提是

- 先冻结粗粒化方案并预注册；
- 同时报告至少两种粗粒化下的 Φ，展示它有多敏感；
- 明确写"Φ 的数值不可跨架构比较"。

## 替代方案

用**跨模块误差结构**（error_corr）作为信息整合的代理。它已在消融矩阵里记录，
且不依赖任意粗粒化。代价是它比 Φ 弱得多，不能声称"整合信息"。
