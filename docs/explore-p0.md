# P0：无奖励探索任务（效价的作用域）

日期：2026-10-26
预注册：`preregistration/stage-p0-exploration.md`（跑数前冻结）
实现：`sim.py` 的 `explore=True`（内在奖励 = 新揭示格子数 × 0.05，0.1 倍代谢）
证据：`evidence/explore_p0.json`、`evidence/explore_p0_raw.jsonl`
运行：`python experiments/run_explore.py 40 1200`

---

## 0. 结论

**跑了两个版本。两版的正对照（H8：学习有作用）都不成立，所以两版都不能判定 H7。**

| 版本 | baseline | valence_off | random（正对照） | H8 p | 判定 |
|---|---|---|---|---|---|
| v2（frontier 距离=99） | 0.548 | 0.545 | 0.563 | 0.655 | 任务未学会 |
| v3（frontier 真实距离） | 0.599 | 0.603 | 0.563 | 0.507 | 任务仍未学会 |

v2 的细节：H7 Δ=+0.004，95%CI [−0.063, +0.072]，d=0.02，p=0.855。
v3 的细节：H7 Δ=−0.004，95%CI [−0.071, +0.069]，d=−0.02，p=0.900。

预注册写的是：「H8 不成立 → 任务未学会，H7 不做判定」。两版都触发了这条。
**所以本文不能得出「效价在探索维度无效」的结论——只能说这个任务族测不出差别。**

证据文件：`explore_p0_v2.json` / `explore_p0_v3.json`（逐 seed 原始数据同名 `_raw_` 后缀）。
`explore_p0.json` / `explore_p0_raw.jsonl` 是 `run_explore.py` 的“最近一次运行”输出，会被覆盖。

## 1. 为什么任务没学会（机制诊断）

部分可观测时，`sim.py` 把策略的「食物方向」复用为「最近的未知格」：

```python
tgt = self.belief.nearest(obs["pos"], 1)      # 没有食物 → None
if tgt is None:
    tgt = self.belief.frontier(obs["pos"])    # 最近的未知格
    d = 99                                    # ← 距离写死 99
```

而模块显著度是 `fd = exp(-food_dist / 10)`。距离 99 → `fd ≈ 0` → `vision` 的 salience ≈ 0
→ 容量 2 的竞争里几乎总被挤掉 → 策略拿到的 `food_dir` 恒为 `(0, 0)`。

**一句话：任务把「往哪探索」的信息喂进了工作空间，但给了它 0 显著度，策略实际看不见 frontier。**

佐证：baseline 的平均内在奖励（−0.012）比随机策略（−0.008）还低，
危险踩踏反而更少（7.0 vs 10.8）——它学会了避危险，但没学会去哪。

### v3：把 frontier 距离改成真的，然后呢

预注册 `stage-p0v3-exploration.md` 只改一处：`explore=True` 时 frontier 用真实曼哈顿距离
（其他条件不受影响）。结果：

| 条件 | 已知格子 | 走过格子 | 危险踩踏 |
|---|---|---|---|
| baseline | 0.599 | 0.358 | 8.8 |
| valence_off | 0.603 | 0.373 | 8.1 |
| random_policy | 0.563 | 0.377 | 10.8 |

H8'：Δ = +0.036，95%CI [−0.031, +0.105]，p = 0.51 → **正对照仍然不成立**。
H7'：Δ = −0.004，p = 0.90 → 按预注册不做判定。

**为什么还是不行**：覆盖率在 1200 步时已经接近饱和（任何策略都能到 0.55–0.60），
学习带来的差距（约 +4pp）低于检出能力；而且随机游走在这个任务里本来就接近高效。
换句话说，**这个任务族的"探索效率"没有足够的分辨力**，不是效价的问题。

按预注册，不再改任务。

## 2. 过程里发现的两件事（都保留在记录里）

1. **效价通路本来是断的**（`valence ≡ 0`）。第一版探索任务（冻结代谢）跑出
   baseline 与 valence_off **逐 tick 完全相同**，查下去才发现是 `affect.compute()`
   两个快照相同。详见 `docs/affect-bug-audit.md`。修复后才有本文的 40 seeds 数据。
2. **冻结代谢会让效价恒为 0**：没有身体变化就没有效价，那版任务等于把 H7 架空。
   已改成 0.1 倍代谢（会饿、会因危险掉完整性），两版都记在这里，没有删。

## 4. 判读

- 这不是「效价在探索里无效」的证据，是「这个任务测不了」的证据。
- 顺带得到一个真结论：**修复后的效价在觅食任务里仍然是阴性**
  （N=60 重跑：进食 3.98→3.72，p=0.20；危险 2.57→2.33，p=0.57）。
  现在这才是干净的阴性——被操纵的量真的在动（`docs/affect-bug-audit.md`），而不是两边都恒为 0。

---

## 5. 下一步

按预注册，**不再改这个任务**。要测「效价在探索维度」需要换一个有分辨力的任务：

1. 覆盖率饱和的任务不行。改成**稀疏信息点**（比如只有少数几个格子有信息，
   其它格子没有）——这样随机游走和定向搜索的差距才拉得开；
2. 或者换成 ReCoN 那种「扫视」任务：信息只在特定注视点出现，测的是注视序列而不是覆盖率；
3. 无论哪种，都必须先让正对照（random 显著更差）成立，再谈效价。

**当前能下的结论**：修复后的效价在**觅食任务**里阴性（N=60：进食 3.98→3.72, p=0.20）；
在**探索任务**里无法判定。两个结论都不支持「效价有可检出的因果作用」，
但也都不是「效价无效」的强证据——它的作用域目前是空的。
