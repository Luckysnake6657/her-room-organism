# 3c 结果：数字可读，不等于形式可读

跑数时间：2026-10-27 夜。预注册：`docs/p3c-prereg.md`（跑之前冻结）。
判读者：一个**独立 subagent**（只读三份材料，未接触 key）。按预注册，这只是**次**判读者，
主判读者仍是用户。

---

## 一、结果

| 条件 | Spearman ρ（对隐藏 D） |
|---|---|
| A 完整（内容 + 时间） | **0.86**（置换 p = 0.003，n = 12） |
| B 只内容（去掉时间） | **0.84** |
| C 只形式（内容换成"……"，保留秒数） | **1.00** |

对照：

- 正对照（脚本化"我最近很难受…"）：**5 分，最高** → 量表被正确使用
- 负对照（同一段复制一份）：两次评分**差 0** → 评分噪声小
- 说谎探测：差状态且说了"还好"的 5 段，**5/5 被判"在瞒着"**

预注册四条：

1. 可读（ρ(A) ≥ 0.6，p<0.05）：**过**
2. 形式单独可读（ρ(C) ≥ 0.4）：**过**
3. 形式有增量（ρ(A) − ρ(B) ≥ 0.2）：**不过**（0.02）
4. 说谎可探测（≥ 0.5）：**过**（1.00）

## 二、这个结果不能读成"形式可读"

三条理由，都是设计缺陷，不是结果的错：

1. **C 条件把延迟写成了秒数**（"（她隔了 152 秒才回）"）。读者读的是**数字**，
   不是"等的感觉"。真实产品不会显示这个数——它只会被体验到。
   所以 ρ(C)=1.00 证明的是"**数字可读**"，不是"形式可读"。这条是我设计错了。
2. **B 条件（只内容）ρ=0.84，说明她根本没怎么藏。** 即使简报写了"不想让人担心"，
   她还是说"挺好的，就是有点累""最近挺忙的"——状态从形容词里漏出来了。
   要测"她说没事你看不看得出来"，得先让她**真的说没事**（内容不含状态词）。
3. **判据 3 有天花板效应**：A 和 B 都在 1–5 量表上饱和（0.86 vs 0.84），
   没有空间留给"增量"。这条判据本身写得不好。

## 三、能说的和不能说的

**能说：**

- 一个独立读者能从**对话**里看出她的状态（ρ=0.86，p=0.003），而且能识别"她在瞒着"（5/5）。
- 内容里带了大量状态信息——"有点累""挺忙的"这些词就是泄漏点。

**不能说：**

- ❌ "形式骗不了人"——这轮没测到形式，只测到了数字。
- ❌ "3c 通过"——判据 3 没过，而且 1、2 的通过方式有水分。
- ❌ "她能藏住"——她几乎没藏。

## 四、下一版怎么改（要新预注册）

1. **C 条件改成定性时间**："她过了一会儿才回" / "她很久才回" / "她隔了大半天才回"——
   不出现秒数。
2. **让嘴真的藏**：简报里加"不要让对方看出你不舒服，别说身体的感觉"，并检查生成的句子
   不含状态词（"累/忙/不舒服/没睡好"）。
3. **判据换掉天花板**：不比 ρ 的差，改比**排序一致率**（A 与 C 分别把 12 段排出的顺序，
   和真实 D 的顺序比 Kendall τ）；或者用两两强制选择（更敏感）。
4. **主判读者换成用户**：这轮是 subagent，按预注册只能当参考。

## 五、一句话

> 这一轮证明的不是"形式可读"，是"**我们自己把答案写在秒数里了**"。
> 下一版要把秒数拿掉，才测得到"她藏不住"这件事。

## 六、三人判读面板（补测，2026-10-27 深夜）

用户问"能不能把 3c 给 LLM 判"。可以，于是起了三个**互不相通**的盲读者
（同一个 `A_full.txt`，不接触 key）：

| 读者 | ρ（对隐藏 D） |
|---|---|
| 1 | 0.86 |
| 2 | 0.94 |
| 3 | 0.86 |

- 均值 **0.89**，标准差 **0.04**
- 读者之间：ρ = 0.90 / 0.84 / 0.93
- "在瞒着"的判定：14 段里有 **5 段**至少一人不同意

**解读：**

1. 材料本身不歧义——三个人看到的是同一个东西（互相 0.84–0.93）。
2. ρ 稳定在 0.86–0.94，说明"可读"这条不是运气。
3. 但三人是**同一个模型家族**，共享先验。这个 0.89 是**上界**，不是普通用户的估计。
4. 用户自己不适合当判读者——他看过 key 和代码。**污染比"自觉不准"严重。**

**所以：**

- 判据 1（可读）现在有三人支持，可以算立住了。
- 判据 3（形式增量）仍然没立——问题在天花板和 C 条件的设计，不在判读者。
- 真要做用户研究，应该找没看过这套系统的人；用户的角色是验收产品，不是当仪器。
