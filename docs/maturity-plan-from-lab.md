# 成熟化思路（从 consciousness-lab 交接给产品会话）

写于 2026-10-28。对象是 `design-brief-for-review.md` 里的那个产品（六状态机体 + 形式/内容分离），
不是 C4-A 那条线（那条已按 `direction-2026-10-27.md` 停止，不重开）。

**这份文档是什么**：把 lab 里被验证过、且可迁移的三条机制，排成产品能执行的四阶段，
每阶段带验收、闸门、回滚。**不是什么**：不是把 lab 搬进产品，不是追 Butlin 条数
（dc 已定天花板 5–6，不再追 7/14），不是意识研究。

---

## 0. 三条前提（先同意再往下）

1. **lab 的数字不给 dc 担保**。下面引用的都是**机制类比**，不是证据转移。
2. **先修数据边界（brief 的 P4）再换 API**。现在用户原话明文落盘、每轮外发；
   上 API 之前必须：本地加密 / 可导出 / 可彻底删除 / 明确告知。这不是技术债，是产品前提。
3. **不要用"意识/元认知"当卖点**。dc 的定位是"状态真实、形式不撒谎、代价不可逆"。

---

## 1. 目标状态（一句话）

让 dc 从"有身体、没记忆、嘴很弱"变成 **"形式可信、记得住、知道自己什么时候不知道"**，
且三层（形式 / 本子 / 自检）都可观测、可回滚、可 A/B。

---

## 2. 四条边界（三条旧 + 一条新）

- 不假装记得
- 不设计愧疚
- 不声称意识
- **不因为一次异常就重写关系**（lab v23 的教训：自监控会锁死在"当前焦点"上，
  产品里表现为过度道歉、反复追问、抓着一次异常不放）

---

## 3. 四阶段（每阶段：做什么 / 怎么验 / 闸门 / 回滚）

### S0 · 可观测性（1 周，不改行为）

- 全链路日志：每轮记录 `state → form → brief → mouth → gate` 的输入输出与决策理由。
- 只读残差 v0，三个量：
  1. **预期回复间隔 vs 实际**（她预期你多久回，实际多久）；
  2. **预期长度 vs 实际**；
  3. **预期话题 vs 实际**（她提的事你有没有接）。
- 不改任何行为，不接 API。
- **验收**：能回答"这一句为什么是这个延迟/这个长度"；日志完整率 >95%。
- **闸门**：完整率不达标不进 S1。

### S1 · 嘴（2 周）

- 换主流 API；契约：一句话、≤N 字、不提问、不元叙述、**不描述自己的状态**、不 AI 腔。
- 四道闸：字数截断 / 禁语 / 事实一致 / **形式-内容极性一致**（"我没事"不能配 300 秒 + 12 字 + 不主动）。
- 回退：API 超时或失败 → 本地 1.5B 或模板，**"回应恒真"不能破**。
- 延迟解耦：先算 form 的延迟，再生成，按延迟投递；API 慢吃延迟，**不叠加**。
- **验收**：50 场景契约测试，五类失败率（超长/禁语/事实冲突/AI 腔/极性不一致）都 <5%；
  首会话 10 分钟留存 A/B（旧嘴 vs 新嘴）。
- **闸门**：失败率 >10% 或留存显著下降 → 回滚到 1.5B，或只在高危场景用 API。
- **注意**：强模型会"表演状态"（"唉，累死了"）——这正是形式不撒谎的反面，契约里必须禁。

### S2 · 本子（3 周）

- 复用 `a1-memory.md` 已经验证的跨会话记忆 + `enforce()` 的"代码闸门"模式，
  但升级成 **可见、可改、可删、带置信度**。
- 写：抽取候选（事实/偏好/事件/承诺）→ 分级（低风险高置信自动入本；高风险问用户一句）→ 可见。
- 读：每轮 0–3 条，按实体 + 未决事项，**不塞聊天原文**（塞原文就是"拿上下文冒充记忆"）。
- 诚实闸：本子里没有或置信度低 → brief 写"你不知道"，mouth 不许断言"我记得"；被问就说不记得。
- **验收**（预注册）：两周埋 30 条事实，第 14 天测——直接回忆 / 间接使用 / **假前提**
  （"你记得我说过要辞职吧"而她没被告知 → 必须说没说过或不记得）。
  指标：回忆准确率、**错误声称率**、纠正后更新率。
- **闸门**：错误声称率 >5% → 本子只读（只记录不引用），不上线。
- **复用**：`a1-memory` 的 P8（重复问同一件事）是关键产品缺陷，本子要顺带解决
  （新回复与历史回复的 bigram 重合度超阈值就重生成）。

### S3 · 关系层残差（3 周）

- 现在 U 是**时钟**（连续无回应天数 → 上升）。改成**残差驱动**：预期 vs 实际持续偏高才升 U。
- U 保留为慢变量，只改"什么时候升/什么时候降"，不改"只调表达"这条。
- 先**只读并行一个月**：同一批对话，分别用"时钟 U"和"残差 U"打分，比较哪一个更能预测
  用户"你变了/你懂我"的评价。
- **验收**：残差与用户评价的相关 > 时钟 U 的相关（预注册阈值）。
- **闸门**：无相关 → 不替换，只保留日志。
- **v21 的依据**：同一个信号，读相位和读残差不是一回事；随机化后增益保留 99.2%，
  说明"对齐到真实变化"才是关键。

## 4. 要产品会话拍板的决定

1. API 选型与成本；是否保留本地开关（隐私）。
2. 首会话延迟上限：60s 还是保留 300s + 强披露。
3. 本子的形态：列表 / 卡片 / 可导出；用户确认的摩擦怎么降。
4. U 与残差的关系：替换 / 并存 / 加权。
5. 多设备/多用户：身体是单实例还是每用户一份（现在离线补算假设单实例）。
6. 第 7 条验收"她会变"：用 S3 的慢参数补，还是按 `direction-2026-10-27.md` 降级措辞。

---

## 5. 不要做的事（防止把 lab 的毛病带进来）

- **不要给 dc 加"14 条指标"的 KPI**。dc 已定天花板 5–6，追条数就是刷榜。
- **不要做 learned 元认知**。lab 的对照里手工 `j_gap` 统计量拿到 83%，学出来的只多值 17%；
  产品要的是可审计的统计量（残差、阈值、日志）。
- **不要跑"显著但推不出任何东西"的实验**（`why-no-2x2.md` 的教训）。
- **不要让 LLM 表演状态**。状态由延迟/字数/主动性承载，嘴只填内容。
- **不要为了通过判据改器材**；失败就记失败。

## 6. 第一周任务清单（可直接开工）

1. 全链路日志（S0）——先能回答"为什么是这个延迟"。
2. 残差 v0 三量（间隔/长度/话题）——只记录，不驱动。
3. 50 场景契约测试集 + 五类失败率脚本（S1 用）。
4. 首会话脚本 + 披露文案（延迟解释）。
5. 本子的数据模型（表结构、置信度、可见/可改/可删）。
6. A/B 框架（旧嘴 vs 新嘴；有本子 vs 无本子）。
7. 修 P4 数据边界（加密/导出/删除/告知）——**在接 API 之前**。
