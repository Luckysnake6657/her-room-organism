# HOT-4：质量空间（稀疏+平滑编码）两次尝试，都没有功能优势

日期：2026-10-26
证据：`evidence/hot4_smooth.json`（本次）、`evidence/ablation_v3_sparse.jsonl`（主矩阵）

## 机制本身是接上的

编码器确实不同（`quality.py`）：

| 值 | one-hot | RBF（平滑） |
|---|---|---|
| 0.1 | [1, 0, 0, 0] | [0.86, 0.43, 0.01, 0.00] |
| 0.5 | [0, 0, 1, 0] | [0.02, 0.65, 0.65, 0.02] |
| 0.7 | [0, 0, 1, 0] | [0.00, 0.13, 0.98, 0.25] |

one-hot 有量化（0.5 与 0.7 落到同一格），RBF 是渐变且重叠的。
所以这不是“没接上”的消融，是**真的有区别但没换来好处**。

## 两次操作性化，都是阴性

**1）主任务（16×16/5 食物，700 步，N=60）**：进食 3.83 vs 3.73，p=0.93。

**2）有限数据（250 步，评估后 125 步，N=60）**——平滑编码理论上该在样本少时占优：

| 条件 | 评估期进食 | 总进食 | 受伤 |
|---|---|---|---|
| one-hot | 0.967 | 2.35 | 0.983 |
| RBF（平滑） | 0.833 | 2.25 | 1.083 |

Δ(评估期) = −0.13（p=0.19）、Δ(总) = −0.10（p=0.38）——**平滑编码反而略差，不显著**。

## 判读

HOT-4 的功能层证据仍然 ❌。原因不是编码没做，而是**这个任务族的“邻近状态”没有共享价值**：
每个格子的最优动作由局部几何决定，两个“相近”的状态并不要求相近的动作，
所以平滑编码的泛化收益无处兑现。

要让它有价值，任务得满足：**状态空间连续、且相邻状态的最优动作相似**
（比如连续控制/有惯性的移动、或奖励随位置平滑变化）。
在当前 grid world + 离散动作 + 单点食物奖励的设定里，这个前提不成立。

## 结论

- 机制：✅ 已实现，且与原版有可验证差异（不是空消融）
- 功能：❌ 两次操作化都无优势
- 判定：保持「架构有、行为阴性」；**不再在本任务族里试第三次**
