## 一、改了什么

```
事件流 ──→ record.build_days()  ──→  DayRecord ×7
                                      │
                                      ├─ 锚点：醒来 / 睡下 / 第一顿 / 出门
                                      ├─ 事件：吃、见人（成/没见着）、受惊、跑回、生病
                                      ├─ 缺口：没吃 / 没出门 / 没见人 / 没睡
                                      ├─ 偏移：相对本人七天中位数的早/晚
                                      └─ 环境：白天长度、傍晚人可能在
                                      ↓
                              render.render_run()  ──→ 人话
```

**动力学零改动**：这一步只增加记录，不碰身体、世界、政策。已验证
（同种子同噪声的 120 次运行逐位相同，见 P0 结果 §八）。

### 记录长什么样

`evidence/p1/record_demo.json`（seed 3 的第 0 天）：

```json
{"wake": 6.0, "sleep": 23.18, "meals": [14.68],
 "gaps": {"no_meal": false, "no_out": false, "no_social": false, "no_sleep": false},
 "wake_shift": "early", "sleep_shift": "usual", "out_hours": 2.16}
```

`wake_shift` 是相对**她自己这七天**的中位数（7.17）算的：6.0 比 7.17 早，记 `early`。
这就是"锚点浮动"的可记录形式——不是绝对值，而是相对自己的偏移。

### 渲染跟着记录走

旧渲染：读事件表拼句子，"缺了什么"要读者自己从空白里猜。
新渲染：先有缺口字段，**缺就直接说出来**——

- `no_meal` → "一整天没吃东西"
- `no_out` → "没什么事，就在屋里待着"
- `social_missed` → "去门廊等了等，人没来"
- `wake_shift=early/late` → "今天醒得比平时早 / 起得比平时晚"
- `sleep_shift=late` → "熬到很晚才睡"

示例：`evidence/p1/rendered_demo.txt`

### 信号与原因（第二轮）

**信号（外生，与她的状态无关）**：天亮、天黑、傍晚人来了/没来/什么时候走、凌晨寒潮。
每天必有 dawn/dusk/person 三种，cold_snap 视温度。

**机会过期**：人来了、她没去见 → 当天记 `missed_window`，结算单里记一次 `missed_windows`。
这不是惩罚，是世界账：窗口到点自己关了。

**原因（只能从前一天或当天更早的事件推出）**：

- `wake_reason`：昨晚/今晨有惊动 → `startled`；当天病重 → `sick`
- `social_cause`：当天有人没来 → `person_absent`

写出来是这样（密集威胁周，`evidence/p1/rendered_dense.txt`）：

> 昨晚被惊动过，今天醒得比平时早，头一顿吃得比平时晚，到门廊那边跟人说了会儿话……
> 昨晚没睡踏实，今天起得比平时晚；到林边找了些吃的；出门转了一阵……

这两句就是理论方案里 A（秩序有前因）和 B（序列可解释）能落地的最小形式——
句子给了"因为昨晚怎样，所以今天怎样"，而不是只报时刻。

## 二、验证

1. **记录自检**（`record.validate`）：每天至少有一个锚点或明确的缺口；进食时刻有序；出门区间不倒挂。
   已加进 `organism/test_invariants.py`（第 8–9 组：记录、缺口、世界信号），9 组全过。
2. **缺口真的被记出来**：能量消融 → 每天 `no_meal`；睡眠消融 → 每天 `no_sleep`（测试里断言）。
3. **信号每天齐**：每天必有 dawn/dusk/person 三种，person 只有"来了/没来"之一（测试断言）。
4. **信号没丢**：用新渲染器 + 新种子（301–312、401–412）各生成 12 对同体两周对比，
   机械编码器仍然 **12/12**（`evidence/p1/week_pairs*`）。

## 三、还没做

1. **原因还只有两条**（被惊动、生病、人没来）。要支持 B（序列刚性）还缺
   "为什么先做A后做B"这类顺序原因——模型里目前没有这个信息。
2. **信号不完整**：只有天亮/天黑/来客/寒潮，没有"外面有人声""天亮得比平时早"这类
   相对信号；E（再校准）要等它们。
3. **离线续算**、**七条时间尺度**：还没动。
4. 老的 `evidence/p0/transcripts` 是旧渲染器的产物，保留作历史，不重生成。
