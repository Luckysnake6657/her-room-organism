# 真实世界层：哪几层能换

写于 2026-10-27 夜。回答"日子能不能从虚拟换成这台机器上真实发生的事"。

---

## 一、现在为什么是虚拟的

虚拟世界是**实验台**：可复现、可消融、可预注册。P0 的 24 个种子、逐边消融、
离线逐位一致，都靠它。真世界做不到"同一个种子跑两遍"。

## 二、分三层

### 第一层：时间与在场——已经接了

`organism/realtime.py` 读 Windows 的 `GetLastInputInfo`：

- `idle_seconds()` / `present(idle_max=300)` / `away_minutes()`
- 实测：`{'idle_s': 0.3, 'present': True, 'away_min': 0.0}`

接到会话回路（`Session.on_presence`）：

- 离开 → 记下时刻，模拟时间**照走**（她继续过日子），但不产生接触；
- 回来 → 按离开时长推进模拟时间，**不自动算接触**（要等她真的被回应）。

跑法：`python -m organism.watch --every 30`（真产品里这就是托盘进程）。

### 第二层：天气与季节——可以接，还没接

`realtime.weather()` 现在是桩，返回 `None`。接了之后她说"下午下了阵雨"就是真事；
不接就是编的，**这一点必须对用户可见**。

### 第三层：她的受伤、感染、威胁——建议永远不接

这些是"世界抽签"。接真实电脑事件（磁盘报错、断网）会变成"她生病"，
无法验证，语义也荒谬。保持合成，但可以**按日期做种子**：每天不一样、当天可复现。

## 三、架构

真实层只产生**世界信号**（在场、天气、时刻），机体动力学、存档、补算都不变：

```
World(sources = {"clock": real, "presence": real, "weather": stub, "hazard": synthetic})
```

## 四、一条诚实边界

界面上必须能标"哪些是真的"：

- 真：时间、你在不在、天气（接上之后）
- 假：她的病、受伤、门廊那个人

不标，就不能说"她有自己的日子"——那只是另一种编造。

## 五、隐私

只取粗粒度：空闲秒数、开关机时刻、离开时长。
不读内容、不记按键序列、不存窗口标题。

## 六、它顺手解决了什么

门廊那个 NPC 之所以能替代"你"，是因为"在场"是假的。
接上真实在场之后，**你不在就是真的不在**；NPC 只压 0.15 的孤独（产品模式），
替代不了。

## 七、两条缺席路径已合并（2026-10-27 夜）

原来"app 关掉"走 `persist.resume`，"人离开键盘"走 `Session.on_presence`，是两条路。
现在两者都产出同一种记录 **`Absence`**（`organism/absence.py`）：

| 字段 | 含义 |
|---|---|
| `kind` | `closed`（app 关掉）或 `idle`（人离开键盘） |
| `minutes` | 离开多久 |
| `gap` | 世界侧的事实：独处天数、吃了几顿、错过几次窗口、病了几分钟 |
| `long` | 是否 ≥ 一天（决定要不要给结算） |

结算只认 `Absence`；短于一天的离开不给结算（问"这段时间怎么样"不会触发）。

**去重**：`on_presence` 回来时会推进模拟并 `_save()`，`saved_at` 随之更新，
所以之后再 `resume` 不会把同一段离开算两遍。
