# HOT-3：元认知驱动的信念更新（接线修好了，但任务撞天花板）

日期：2026-10-26
预注册：`preregistration/stage-hot3-belief-update.md`
证据：`evidence/hot3.json`

## 0. 一句话

**原来的 `belief_update_on` 是空接线**（`mc < 0.5` 从不触发，因为 agency_confidence 均值约 0.9）；
改成连续调制后行为确实变了，但**任务撞天花板**（5 食物和 12 食物都被吃光），
H1 无法判定。

## 1. 发现的接线问题

`policy.act` 原来是：

```python
if meta_conf is not None and meta_conf < 0.5:
    eps_eff *= 1.3
```

本平台上 `agency_confidence` 均值 ≈ 0.9，**永远进不去这个分支**。
也就是说 HOT-3 所谓的"元认知驱动"从来没有生效过——和效价恒为 0 是同一种错误
（机制写了，条件永不满足）。

改为连续调制：

```python
unc = 1.0 - meta_conf
eps_eff *= (1.0 + 0.6 * unc)
if hint is not None:
    q[hint] += 2.0 * unc
```

## 2. 结果

| 任务 | 条件 | 进食 | 危险 | 死亡 |
|---|---|---|---|---|
| 5 食物 | planner_on | 5.0 | 4.6 | 0.00 |
| 5 食物 | belief_update_on | 5.0 | 4.8 | 0.00 |
| 12 食物 | planner_on | **12.0** | 5.05 | 0.12 |
| 12 食物 | belief_update_on | **12.0** | 5.17 | 0.12 |

配对置换：进食 Δ=0.000（p=1.00）、危险 Δ=+0.117（p=0.85）。

## 3. 判读

- **不是阴性，是无判定**：两组的进食都等于食物总数，**天花板效应**。
  任务太容易，元认知再怎么调也换不来更多进食。
- 危险踩踏没有显著差异（p=0.85），说明连续调制既没帮上忙也没添乱。
- 接线问题是**真实发现**：它解释了为什么此前所有涉及 `belief_update_on` 的代码都是死的。

## 4. 要继续测 HOT-3，需要什么

一个**不会饱和**的任务：
- 食物足够多（≥30）或时间是原来的 1/3，使"吃光"不可能
- 或者把指标换成"单位时间进食率"而不是总进食
- 或者制造"信念会过期"的压力（食物会坏/会迁移），让"什么时候该更新信念"成为真问题

这是任务设计问题，不是机制问题；本文件只记录到"接线已修、任务无效"为止。


## 5. 第二次尝试：30 食物仍然吃光（2026-10-26 追加）

预注册 `preregistration/stage-hot3-nonsaturating.md`：把食物加到 30（16×16 里接近饱和），
指望 700 步吃不完。

结果：`planner_on` 与 `belief_update_on` **都吃到 30.0**（全吃光），
危险 5.73 vs 5.53（p=0.72）。

按预注册的 H0（任一组 ≥29 即判天花板）→ **仍然无判定**。

**结论**：这个 agent 在 16×16 上太高效（约 0.043 次进食/tick），
700 步内 30 个食物不够；要测 HOT-3 得换任务形态（食物会迁移/会坏、或大幅缩短步数），
而不是继续加食物。


## 6. 第三次：食物迁移任务（仍撞天花板）

预注册 `preregistration/stage-hot3-dynamic.md`：`dynamic=True`，食物每 60 tick 迁移 20%。

| 条件 | 进食 | 危险 | 死亡 |
|---|---|---|---|
| planner_on | **11.98 / 12** | 6.55 | 15% |
| belief_update_on | 11.93 / 12 | 5.72 | — |

- 进食 Δ=−0.05（p=0.25）：**又是天花板**（12 个食物全吃光）
- 危险 Δ=−0.83（**p=0.067**）：元认知组少踩 0.8 次危险，接近显著但没过线

**判定**：按 H0（任一组 ≥11）→ 仍无判定。但这一版出现了方向正确的边缘信号
（少踩危险），值得在**更大网格**（32×32）里重做——那是唯一能让 agent 吃不完的设置。


## 7. 第四次：32×32 大图 —— 进食仍饱和，且元认知组更危险

预注册 `preregistration/stage-hot3-32x32.md`：1024 格、12 食物、700 步。

| 条件 | 进食 | 危险 | 死亡 |
|---|---|---|---|
| planner_on | **12.0 / 12** | 0.85 | 0% |
| belief_update_on | **12.0 / 12** | 1.22 | 0% |

- 进食再次**完全饱和**（12/12），这说明这个 agent 的觅食效率远高于我对任务的估计
- **危险：Δ=+0.37，p=0.043** —— 元认知组**显著更危险**

按预注册 H2（进食不变差、危险变差 → 无收益）→ **判"无收益，且轻微有害"**。

**HOT-3 的最终判定**：
- 接线问题是真的（原实现从不触发），已修
- 修好之后，在四个任务变体里**没有一次带来收益**；32×32 上还显著更危险
- 解释：连续元认知调制 = 低置信时提高探索率 + 加重规划提示，
  在觅食任务里"探索更多"等于"更常靠近危险"
- 状态：**partial 不变**，功能层证据判负
