# 物理回路尝试记录（AE-2）

日期：2026-10-26

## 设备

- 摄像头：可用（640×480，`cv2.VideoCapture(0)` 正常）
- 音频：Razer USB Sound Card（麦克风 + 扬声器同一设备）

## 声学回路（失败）

目标：扬声器放 8kHz 短音 → 麦克风收回 → 系统检测"这是我发出的"。

| 版本 | 结果 |
|---|---|
| v1（440Hz，playrec 同时） | ON/OFF 能量比 0.50（反向） |
| v2（8kHz，录音线程先起，播放插在 0.5s） | **ON 的播放窗口能量精确为 0.0000**，OFF 的同窗口 0.0995 |

**判读**：不是时序问题，是设备不支持全双工——播放时麦克风被静音或独占。
0.0000 这个精确的零说明录音流在播放期间没有数据，不是"没收到声音"。

## 视觉回路（未做）

可以走，但需要系统控制屏幕内容（显示色块）再让摄像头看回来。
当前用户在打游戏，抢屏幕不可接受。

## 视觉回路（失败，v3）

用户允许占用屏幕后重试：白屏全屏闪 1.4 秒，摄像头连续采样取峰值。

| 项 | 值 |
|---|---|
| 基线亮度 | 60.85 |
| 白屏峰值 | 62.89 |
| 比值 | **1.03** |
| 白屏后 | 60.80 |

**只有 2% 的亮度变化**，不构成可检测的因果通道。

补充观察：摄像头抓到的画面是**键盘/桌面**（很暗，只能看到键盘轮廓），不是屏幕。
所以"屏幕光照亮键盘"这条间接路径也不成立——屏幕的光照不到摄像头视野里。

## 结论

**AE-2 的 L4 在这台机器上不可得。** 三条路都试过：

| 路径 | 失败原因 |
|---|---|
| 声学（播放→麦克风） | USB 声卡不支持全双工，播放时录音窗口能量为 0 |
| 视觉（屏幕→摄像头） | 摄像头看不到屏幕，白屏只带来 2% 亮度变化 |
| 视觉（屏幕照亮键盘） | 同上，摄像头视野里是暗键盘，光照不到 |

保持 partial L3，表里注明"物理回路受设备限制"。

## 剩余可选路径（都需要外部条件）

1. 换一个支持全双工的声卡/耳机（带独立麦克风输入的）
2. 用第二块屏幕或手机做"自照"目标
3. 等用户不打游戏时，允许系统短暂占用屏幕
