# "等待过期"机制：决定与设计

2026-10-27。决定：**做。但改一处——她不说她等过，但过期会"漏"。**

---

## 一、机制

她心里有几件"等你回来再说"的事（`pending`）。每件有：

- **内容**（想告诉你的事 / 想问你的话）
- **产生时间**
- **过期条件**（不是统一时长——按事情的性质：今晚的天气明天就没意义了；想问你的决定，三天后她自己定了）

超时之后：**它自己了结**，而且**她不会告诉你她等过**。

但她会在之后的对话里**顺口带出来**：

> "那事我自己弄了。"
> "本来想问问你的，后来就算了。"

**这不是她宣布"我等过"，这是后果漏出来了。**

## 二、为什么要"漏"

如果她完全不说，用户永远不知道错过了什么 → **暗箱惩罚**，违反"透明"那条公平规则。

如果她直接说"我等了你三天" → **情绪惩罚**，违反"不针对情绪"那条。

**"事后顺口带出"同时避开了两者**，而且这就是真人的做法：
没人会说"我等你等到心凉"，但会说"那事儿啊，我早弄完了"。

## 三、文献支持（概念层面）

| 概念 | 内容 | 对我们的用处 |
|---|---|---|
| **Zeigarnik 效应**（1927） | 未完成的任务比完成的记得更牢 | 说明"没说完的事"天然会留在心里，不用我们硬造 |
| **格式塔的"未完成事件"**（Perls） | 未表达的情绪会持续要求closure | 过期的那个"了结"，是真的把它合上了——所以有代价 |
| **等待作为时间约束**（社会学/时间研究） | 等待结构化了期待 | 等待的长度本身在改变关系的形状 |

**核对状态**：这三个是标准概念，本次检索到的多为二手期刊（日文/中文），

## 四、三条公平约束（接上一份文档）

1. **可推断**：过期不是随机的，用户事后能推出来（她说过在等）
2. **有上限**：pending 数量有上限，不会无限堆积
3. **不指责**：她带出来时用的是陈述语气，不是抱怨语气

**第三条是红线。** 一句"本来想问问你的，后来就算了"是关系；
一句"你都不在，我只能自己弄了"是勒索。**同样的信息，不同的重量。**

## 五、为什么这个机制值得做

- **最便宜**：我们已有 `pendingThought` 和记忆的 `mentioned_in_idle` 雏形
- **最像人**：人会停止等待，这是最普通也最真实的失望
- **代价真实但不残忍**：错过就是错过，没有惩罚，也没有死亡
- **它测的是"缺席"，不是"态度"**——正好符合"代价来自世界"那条线

## 六、判据

| # | 判据 | 怎么测 |
|---|---|---|
| 1 | 过期真的发生 | 离开 3 天，回来时 pending 应当已被处理 |
| 2 | 事后会漏 | 之后 2–3 轮内，她能自然带出来（不是被问出来的） |
| 3 | 不指责 | 带出来时不含指责性措辞（可正则检测） |
| 4 | 可推断 | 独立评分者看她离开前的对话，能预料到"有件事在等" |
