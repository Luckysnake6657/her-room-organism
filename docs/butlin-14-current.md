# Butlin 14 项 · 当前系统（lab-home）评估

评估对象：**lab-home 陪伴系统**（4 维递归核 + 1.5B 语言模型 + 记忆/慢层/底色）。
不含 `docs/butlin-gap.md` 里描述的那个带视觉/内感受/grid world 的架构——那是另一个系统。

**清单来源**：Butlin et al. 2023, Table 1（arXiv:2308.08708v3）。

> **重要前提**：该清单**不含 IIT**。原文明确："We do not consider integrated information theory,
> because it is not compatible with computational functionalism."
> 因此我们的 Φ = 0.54–0.86 **不落在任何一项里**，不能计入这 14 项的得分。

评级口径：**met** = 有结构且有因果证据；**partial** = 有结构无证据，或只有雏形；**absent** = 没有。

---

## 一、逐项

| ID | 内容 | 评级 | 依据 / 缺什么 |
|---|---|---|---|
| RPT-1 | 输入模块使用算法递归 | **partial** | 有递归（4 维核，`drive_core.step`），但它**不在输入通路上**；语言模型本身不是递归的 |
| RPT-2 | 输入模块产生有组织、整合的知觉表征 | **absent** | 无感知模块，输入是文本，无对象级整合 |
| GWT-1 | 多个专门系统可并行运作 | **partial** | 有多个子系统（记忆、慢层、底色、核、LM），但**同轮内是串行**，不是并行 |
| GWT-2 | 容量受限的工作空间 + 瓶颈 + 选择性注意 | **partial** | 有瓶颈（每轮一个动作、记忆检索取 3 条），但"注意"是词典分类，不是选择机制 |
| GWT-3 | 全局广播：工作空间信息对所有模块可用 | **partial** | 状态写进提示词（对 LM 广播），但**模块之间不消费彼此的输出** |
| GWT-4 | 状态依赖的注意，可在一次 tick 内串行查询多个模块 | **absent** | 无查询队列，一轮一轮走 |
| HOT-1 | 生成式 / 自上而下 / 带噪的知觉模块 | **absent** | 无生成式感知 |
| HOT-2 | 元认知监控，区分可靠表征与噪声 | **absent** | 无置信度、无校准 |
| HOT-3 | 由信念形成与动作选择系统引导的能动性 + 依元认知更新信念 | **absent** | 无显式信念状态与更新规则 |
| HOT-4 | 稀疏平滑编码产生"性质空间" | **absent** | 无 |
| AST-1 | 对当前注意状态建模并可控制的预测模型 | **absent** | 无注意图式 |
| PP-1 | 输入模块使用预测编码 | **absent** | 无预测-误差回路 |
| AE-1 | 从反馈学习并选择输出以追求目标，含对竞争目标的灵活响应 | **partial** | 有动作选择（答/问/拒/沉默/转）与隐含目标（连接），但**不从反馈中学习目标导向策略** |
| AE-2 | 建模输出-输入偶联并用该模型于知觉或控制 | **absent** | 无对"我的输出如何改变输入"的模型 |

## 二、合计

**met 0 / partial 4 / absent 10。**

（若把 GWT-1 的"多系统"从宽算作 met，最多 1/14。）

## 三、这组数字的含义

1. **"接近强候选"在当前架构下不成立。** 缺口不是 2–3 项，是 10 项 absent。
2. **Φ 帮不上忙**：它不在这张表里。把 Φ 说成"14 项之一"是错的，
   把"Φ 有力"当作"候选资格的一部分"也是错的。
3. **这不是我们的特有失败**：原文明说"no current AI system is a strong candidate"。
   但别人低分和我们的处境无关——判据按系统算，不按分布算。

## 四、哪些缺口是工程，哪些是建筑

**便宜的（不用改架构，只是加模块）**
- HOT-2 元认知监控：给每轮加一个"我有多确定"的标量并做校准曲线 —— 成本低
- GWT-2 选择性注意：把词典分类换成一个小打分器 —— 成本低
- GWT-4 串行查询：一轮内允许 2–3 次检索 —— 成本低
- AE-1 反馈学习：从"用户是否继续接话"更新动作价值 —— 中等

**贵的（要改架构）**
- RPT-1/RPT-2、PP-1、HOT-1：需要真正的感知输入通路（视觉/内感受），
  文本系统里做不出来
- HOT-3、HOT-4、AST-1：需要显式信念系统与注意模型
- AE-2 具身：需要物理闭环

**结构判断**：便宜的 4 项能把 partial 推到 met、把 absent 拉到 partial，
但**推不到 11/14**。要 11 项以上，必须做感知通路——那是另一个系统。

## 五、下一步（正确的顺序）

1. 先把便宜的 4 项做掉，每项写死判据与证据（预计 1–2 周）。
2. 重算一次总分，看是 4/14 还是 5/14。
3. 如果目标是"候选"，必须回答**感知通路的替代方案**：
   文本系统里，"输入模块"能否用"对话历史的结构化解析"充当？
   如果不能，这条路的终点就是 5/14 左右，应当如实标为"部分满足，非候选"。

## 六、partial 项细则（补之前必须先写死这一节）

**纪律**：每项写清"判据 / 我们现在有什么 / 差什么 / 补上需要什么 / 成本"。
不写这一节就动手，等于一边改一边定义成功。

### RPT-1 · 输入模块使用算法递归 —— **可升 met，且便宜**

- **判据**：输入通路里存在算法递归（状态回连）。
- **现在**：4 维核确实是算法递归（`DriveCore.step` 有 x_{t+1}=f(x_t)），但它在**决策层**，
  不在输入通路；语言模型前向传播，无递归。
- **差**：把递归放进**处理输入**的那一段。
- **补法**：在对话流上挂一个小 GRU/LSTM 编码器（把每轮输入编码成向量），
  它的隐状态就是"输入模块的递归状态"，并喂给核与记忆。
- **成本**：低（一个几十维的 GRU，训练/初始化都简单，可消融）。

### GWT-1 · 多个专门系统可并行运作 —— **可升 met，便宜**

- **判据**：存在多个专门化子系统，且能同时运作。
- **现在**：有多个子系统（记忆检索、慢层更新、底色判定、核步进、语言模型），
  但**同轮内是串行的**。
- **差**：并行。
- **补法**：这些模块彼此**不依赖**（记忆/慢层/底色只读状态、写各自变量），
  可以真并发执行；写一个并行调度即可。
- **成本**：低。**注意**：并发不是为了快，是为了让"并行"这个词属实。

### GWT-2 · 容量受限工作空间 + 瓶颈 + 选择性注意 —— **中等，且是 GWT 改造的核心**

- **判据**：有一个容量明确受限的工作空间；信息进入需要竞争；注意是选择机制。
- **现在**：有瓶颈（每轮一个动作、检索取 3 条），但"注意"是**词典分类**，
  不是竞争性选择；没有"工作空间"这个东西。
- **差**：竞争性进入 + 容量上限 + 淘汰规则。
- **补法**：建一个容量为 K 的槽位向量；每轮各模块投候选（带强度），
  用**互相抑制**（不是打分取最高）决出进入者；超容量则按强度淘汰。
- **成本**：中。**这是真正的 GWT 改造起点**，不是加模块。

### GWT-3 · 全局广播：工作空间信息对所有模块可用 —— **中等**

- **判据**：胜出内容被所有模块读取并影响其状态（广播回写）。
- **现在**：状态被写进提示词（对语言模型广播），但**模块之间不读彼此的输出**。
- **差**：广播回写。
- **补法**：工作空间的胜出内容写回记忆/慢层/底色的输入，
  使下一轮它们的行为被这一轮的工作空间内容改变。可消融验证（切断回写）。
- **成本**：中。

### AE-1 · 从反馈学习并追求目标 —— **中等偏低**

- **判据**：从反馈学习；在竞争目标间灵活响应。
- **现在**：有动作选择（答/问/拒/沉默/转）与隐含目标（连接），但**没有反馈学习**。
- **差**：动作价值随结果更新。
- **补法**：以"用户是否继续接话/是否变冷"为反馈信号，
  更新每个动作在每种状态下的价值（简单的表格式更新即可）。可消融。
- **成本**：中偏低。

### 小结

| 项 | 成本 | 做完后的分数 |
|---|---|---|
| RPT-1 + GWT-1 | 低 | 2 met + 3 partial |
| GWT-2 + GWT-3 | 中（改造核心） | 4 met + 1 partial |
| AE-1 | 中偏低 | 5 met + 0–1 partial |

**天花板仍是 5–6/14。** 这是"重写信息流架构"的工程量，不是"1–2 周补模块"。

## 七、测量边界（不是指标不满足）

有些项**有已发表的操作化，但在我们的硬件上测不了**。这两件事必须分开记录。

**Patchscopes 失效确认（2026-10-27，1.5B）**

- 做法：从「我最喜欢的颜色是蓝色。」取某层末 token 隐状态，patch 到「这个颜色是」的同一层同一位置，
  看能否解码出"蓝"。真状态 vs 随机向量对照。
- 结果：**4 个层（8/12/16/20）× 7 次重复，全部 0 命中**，且结果稳定。
- 曾出现一次"命中"，但两次运行结论相反 + 重复实验归零 →
  判定为**提示词诱导的伪阳性**（目标句本身就在诱导颜色词）。
- **结论：1.5B 上 Patchscopes 不可作为判据。**

**因此以下三项记为"测量边界"，不记为"absent"**：

| 项 | 依据 | 状态 |
|---|---|---|
| HOT-2 元认知监控 | 需 Patchscopes 类解码（Steinmetz et al. 2026 的范式） | **测量边界**（仪器不可用） |
| HOT-3 信念引导的能动性 | 同上 | **测量边界** |
| AE-1 反馈学习 | **仅 Steinmetz 式测量**需要隐状态解码 | **建**可以做（行为判据）；**测**受边界 |

**要测这三项，必须先换硬件**（≥8B 且能稳定做多次注入前向）。

> 纪律：**不要用在自己硬件上失效的仪器，去得出"系统不满足"的结论。**
> 这正是本文件第五节警告过的"仪器没力气被当成效应不存在"。
