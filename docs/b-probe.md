## 迭代 1（预注册原版）

任务：子集 S ⊂ {1..4}，|S|≥2，11 种规则，24 tick。

| 条件 | 正确率 |
|---|---|
| 耦合 | 0.496 |
| 拆开 | 0.504 |

**两边都停在 0.50。** 但这次结果**不可解释**——因为没有上界对照，
分不清"任务不可解"和"训练失败"。这正是本项目被坑过两次的那类错误
（效价的 `p=1.000`、EI v1 的均匀填充），所以当场不作结论，先补上界。

## 迭代 2（改任务：2 条规则 + 48 tick）

任务：S 只有 {0,1} 或 {2,3} 两种，48 个 tick 累积证据。

| 条件 | 正确率 |
|---|---|
| **oracle（知道规则，上界）** | **1.000** |
| **belief-oracle（不知规则，错了就换，可行性下界）** | **0.990** |
| 耦合（60 代 ES） | **0.613** |
| 拆开（60 代 ES） | 0.546 |

**结论：任务可解，上界 0.99；耦合版有学习（0.50→0.61），方向正确。**
但离预注册判据（耦合 ≥0.80）还远，**不算有信号**。

## 发现的一个真泄漏

拆开版的每个模块都能读到 `err`（上一 tick 对不对）。
**这个误差信号是一条共享通道——也就是一次全局广播。**

所以"拆开"版并不是"完全无整合"，它共享了 1 个比特。这解释了为什么它没停在 0.50
（其中一个种子到了 0.597）。

**修法**：拆开版的反馈改成 **yoked**（把误差信号在回合间打乱，统计相同但内容不携带信息）。
这是 sham lesion 的又一次应用——同一个教训，第三次出现。

## 迭代 3（训练加长：200 代）

| 条件 | 60 代 | 200 代 |
|---|---|---|
| 耦合 seed=0 | 0.611 | **0.639** |
| 耦合 seed=1 | 0.620 | **0.613** |

**加了 3 倍训练，只涨了 0.01–0.03，然后停在 ~0.62 平台。**

所以弱的不只是训练时长——**这个架构 + ES 在这个任务上到不了 0.80。**

## 一个更难受的诊断

如果为了"能训出来"而把任务改简单（比如把规则固定成一条、用固定随机储备池 + 岭回归读出），
那么结果就退化成教科书事实：

> "奇偶不可分解、XOR 不可线性分离"——1986 年就有了。

也就是说：

- **任务做得难**（在线推断隐规则）→ 我们训不动（卡在 0.62）。
- **任务改到训得动** → 结论是已知的，不构成新结果。

**这是这条路线真正的天花板，而且它比"训练不够"严重得多。**

## 最终判定：B 关闭

| 项 | 结果 |
|---|---|
| 任务可解 | ✅ 上界 0.99 |
| 学习发生 | ✅ 0.50 → 0.62 |
| 达到判据 | ❌ 平台 0.62，加训练无效 |
| 控制干净 | ❌ 误差通道泄漏 |
| **能否给出新结果** | ❌ 训得动的版本结论已知，训不动的版本训不动 |

**按预注册的规矩，这条线关闭，不调参重试。**

代价：2 小时。收益：省下原本计划的 3 周。
