# 证据协议（双层 + 三分类）

冻结时间：2026-10-26
适用：`src/butlin.py` 的 14 项指标，以及以后任何新加的模块/指标。

这个协议是效价事故（`docs/affect-bug-audit.md`）逼出来的：那次“消融有效、行为阴性”
看起来像结论，其实是**被操纵的量恒为 0**——两边都是 0，p 自然是 1。
所以任何主张必须先过第一层。

---

## 1. 两层

| 层 | 问题 | 通过条件 | 工具 |
|---|---|---|---|
| **L1 扳动层**（manipulation check） | 消融真的改了它声称改的那个量吗？ | 扳动量按预期方向变化，且幅度不可忽略 | `experiments/audit_manipulations.py` 的 knob |
| **L2 后果层**（consequence） | 改了之后，行为/功能有可检出的变化吗？ | 同 seed 配对置换 p<0.05，且方向与理论预期一致 | 同一脚本的行为对比 |

**闸门规则**：

1. L1 ❌ → 主张**作废**（不是阴性），先修实现，禁止写进报告
2. L1 ✅ + L2 ✅（方向对） → **功能层证据**
3. L1 ✅ + L2 阴性 → **只有架构层证据**，可以写“实现了”，不能写“在起作用”
4. L1 ✅ + L2 显著但方向与预期相反 → 记“有害”，不能当支持证据（如 HOT-1 的预测器）

## 2. 三分类（决定一项能不能进功能层计数）

| 类 | 含义 | 能否进功能层 | 例子 |
|---|---|---|---|
| **A 可消融** | 有对应消融条件，能同时测 L1 和 L2 | ✅ | GWT-2、RPT-1、HOT-2、AE-1 |
| **B 仅架构** | 实现了，但没有能单独扳动的消融（或消融本身不成立） | ❌（只能算架构层） | GWT-1、HOT-3、RPT-2 |
| **C 外部证据** | 证据来自硬件/外部实验，不在 sim 内 | ✅（但走单独协议） | AE-2 |

## 4. 条件性证据的记法

像 AST-1 这种“换一个任务才有作用”的情况，协议规定：

1. **主任务口径**决定功能层计数（AST-1 因此仍记 ❌）
2. 条件性结果单独写进文档，标注**任务依赖**，并写清“需要什么代价/结构才显现”
3. 条件性结果**不能**用来改写主任务口径的判定，只能在讨论里当线索

---

## 5. 新增模块的准入条件

任何补充模块（DCM、临界、双向、TRO 扩展……）要进系统，必须先满足：

1. 有一个**只扳动它**的条件（否则无从做 L1）
2. L1 有明确的期望方向与量级
3. L2 有配对设计（同 seed）
4. 预注册写在 `preregistration/` 下，且写死“阴性就关”

缺任何一条 → 只能进架构层，或者在报告里明确标“未评估”。

---

## 6. 禁止清单

1. 调参到通过（改阈值/代价/步数/seed 数换结论）
2. 没有 L1 的阴性（效价教训）
3. 把架构层数当功能层数
4. 用条件性证据改写主口径判定
