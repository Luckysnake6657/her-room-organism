## 2. 首次对比（真核 vs 假核）—— 有信号，但不可直接采信

| | 真核（递归） | 假核（x=tanh(u)） |
|---|---|---|
| note / reflect / rest / do_task | 108 / 76 / 114 / 2 | **0 / 300 / 0 / 0** |
| 核读出与最高分的分歧率 | 0.763 | **1.000** |
| 平均读出 margin | 0.351 | 0.250 |

**表面结论**：没有递归，系统立刻塌成单一动作（300 次全是 reflect）。这说明核是承重的。

**但这个差异不可采信**，原因有三：

1. **塌缩是退化的**。假核 `x=tanh(u)` 的读出被嵌入的固定几何主导，等于"永远选同一个"。
   一个永远选同一动作的对照，跟任何有变化的系统都会显著不同——**这是格式性差异，不是功能差异**。
2. **假核没有做方差匹配**。正确对照应该是"输出方差与真核相近，但没有递归/没有历史"，
   否则测的是"有没有输出"，不是"有没有整合"。
3. **分歧率 0.763 本身也可疑**。它说明核经常推翻分数排序——可能是真结构，也可能只是
   嵌入向量碰巧与 W 的主方向不对齐。需要打乱 W（λ 匹配）来判断。

## 3. 因此 A1 必须先修两件事

1. **假核对照改成方差匹配**：用随机正交变换 + 同方差噪声代替 `x=tanh(u)`，
   使其行为分布与真核可比，只去掉递归与历史。
2. **世界要活**：任务队列现在跑两次就空，`do_task` 只出现 2 次；inbox 恒为 0。
   需要任务生成器与（模拟的）对话流，否则四个驱动里有两个长期不动。

## 4. 另一个观察

`rest` 114 次：代谢驱动在 300 周期里反复把休息顶上来。不是 bug，但说明驱动速率
（`persona/drives.json`）会让系统偏向"低耗动作"。A1 接 LLM 之前要先调平，
否则提案多样性会被驱动常数锁死。

## 5. 结论

**A0 通过，可以进 A1。** 但 A3 的 2×2 对照设计必须按 §3.1 重写——
现在这个版本会得到一个"显著但无意义"的结果，那比阴性更危险。
