# 决定：人格提示词切换（2026-10-30）

## 决定

采用框架提示词（132 字）替代现行人格提示词（约 8600 字），**分阶段上线，保留回滚**。

## 依据

| 证据 | 值 |
|---|---|
| 盲选（40 对） | B 胜 21/40 = 52.5%，CI [37.5%, 67.1%] |
| A/A 对照 | 首位 8/10（p≈0.11），提示噪声/轻微位置偏好 |
| 风格 JS | 0.094（≤0.10） |
| 不复读 | 0.584（<0.6） |
| 换嘴 | ΔJS 0.016 |
| 文体 proxy | AUC 0.912；A/B 的 P(她) 0.770/0.752 |

## 诚实表述

**不是"框架版更优"，是"当前分辨率下未检测到差异，且提示词长度降 98%"**。
按预注册， superiority 未成立；本决定属于**等价前提下的架构选择**，不是科学上的胜出。

## 上线方式

1. 影子一周：`--persona-shadow` 继续记录，不改变行为
2. 一周后无异常 → bridge 改用 `persona.prompt` 渲染
3. 监控：对话自然度、重复率、记忆引用正确率
4. 回滚：bridge 切回旧提示词；organism 侧 `--persona-shadow` 可随时关

## 风险

- 盲选无法证明等价（CI 宽），真实对话可能暴露差异
- 提示词变短后，人格细节靠画像+样例，边界情况可能掉
- 样例来自她的历史，注意隐私，不外传

## 重要修正（2026-10-30 晚）

原先"8600 字 → 201 字"的对比**不严谨**：
baseStable 里不只有人格，还有工具说明、群聊规则、记忆纪律、边界等**必需规则**。
我们的 201 字只覆盖"人格/风格/意图"，**不能直接替换整个 baseStable**。

结论：
- 本实验验证的是"人格与风格的框架化"，不是"整段提示词可删"
- 真正切换 = 把人格块换成 persona.prompt，**其余规则块保留**
- 这是一次结构性改动，必须单独做、单独验证，不能热切

## 审计后的最终决定（2026-10-30 晚，管理员授权自行决定）

**决定：暂不切换，保持旧提示词。**

理由（严谨优先）：
1. 审计显示 baseStable 的 60%（TONE_AND_LAYOUT，5124 字）确实是说话风格，**可替换**；这修正了"工具规则占大头"的误判。
2. 但已有盲测只覆盖"人格片段"（201 字 vs 长人格），**没有测过"整段 TONE_AND_LAYOUT 被替换"**。
3. TONE_AND_LAYOUT 里混有边界规则（不人身攻击、不当解说员、别拿"行/好的"起句）——这些不在 201 字里，替换会丢。
4. 直接热切的风险（行为退化）大于收益（省 token），且回滚只能靠备份。

## 下一步（切换前必须做）

1. 把 TONE_AND_LAYOUT 拆成"风格"与"边界"清单
2. 构造三版提示词：旧版 / 风格替换版 / 风格+边界替换版
3. 各跑 20 条相同语境（含工具、群聊、记忆场景），**人工盲选 + 规则命中检查**
4. 只有"像她"不降且边界规则全在，才切换
5. 切换仍走 `personaMode` 配置 + 备份回滚
