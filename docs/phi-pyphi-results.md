# PyPhi（IIT 3.0 参考实现）结果：Φ 与打乱零模型不可区分

日期：2026-10-26
实现：`experiments/run_phi_pyphi.py`　证据：`evidence/phi_pyphi.json`
环境：Python 3.12 + **PyPhi 1.2.0**（PyPI 直取 wheel，见 §1）

---

## 0. 一句话

用参考实现算，**Φ ≈ 0.004–0.011，和打乱时间序的零模型（0.009–0.017）同量级，
而且谁高谁低在两次运行之间会翻转**。所以：**没有证据支持"模块层存在不可约的整合"。**

## 1. 装 PyPhi 的过程（为什么之前说"装不上"）

| 尝试 | 结果 |
|---|---|
| PyPhi 2.0.x | 要求 **Python ≥ 3.13**，本机 3.12；`py -0p` 里那个 3.13 是**注册表残留**，exe 不存在 |
| python.org 下载 3.13 | 连接被关（超时） |
| winget 装 3.13 | 无输出、退出码 1（被拦） |
| pip 装 PyPhi 1.2 | pip 在 workspace 里建 `pip-unpack-*` 被拒（EACCES），临时目录也被拒 |
| **直取 wheel + 解包** | ✅ 成功 |

做法：`tools/fetch_wheels.py` 从 PyPI JSON 拿 wheel（绕开 pip 的临时目录），
解包到 `pylib312/`，再补 `pyemd==2.0.0`（现在有纯 Python 轮子）、`pot`、`tblib`、`redis`、`pymongo`。

**两个兼容性补丁**（PyPhi 1.2 是 2022 年的代码，跑在 3.12 上）：
1. `from collections import Iterable` 等 → `collections.abc.*`（3.10+ 已移除这些别名）
2. 配 `pyphi.config` 时要关掉 `PARALLEL_CUT_EVALUATION` 等（旧版没有 `PARALLEL` 这个键）

补丁只动 `pylib312/pyphi` 里的 import 行，不改算法。

## 2. 校准（先证明装对了）

| 合成系统 | Φ（8 个状态的平均） |
|---|---|
| 三个独立节点 | **0.000** |
| 三节点多数投票（强耦合） | **0.247**（0.16–0.34） |

独立为 0、耦合显著为正 → 参考实现在本机工作正常。

## 3. 数据结果

状态集：按 baseline 访问频率取**前 3 个状态**，两个条件共用；Φ 取这三个状态的平均。
零模型：打乱时间序 30 次。

| 运行 | 条件 | Φ | 零模型均值 | 零模型最大 |
|---|---|---|---|---|
| N=40, 15 次置换 | baseline | 0.0112 | 0.0092 | 0.0127 |
| N=40, 15 次置换 | workspace_off | 0.0134 | 0.0090 | 0.0133 |
| **N=60, 30 次置换** | baseline | **0.0043** | **0.0171** | 0.0219 |
| **N=60, 30 次置换** | workspace_off | **0.0043** | 0.0158 | 0.0241 |

## 4. 三条判读

**1. 没有"高于机会"的整合。**
N=60 时观测 Φ（0.0043）**低于**零模型（0.0171）。也就是说：真实的时序结构，
在这套 TPM 上算出来的 Φ 还不如打乱时间序的版本。

**2. 估计本身不稳定。**
N=40 时观测 0.0112 > 零模型 0.0092，N=60 时反过来（0.0043 < 0.0171）。
3 个元素、8 状态、按 3 个状态取平均——**这个量在当前数据规模下噪声很大**，
不能拿单次运行的高低说事。

**3. 与自实现版本不一致，这次以参考实现为准。**
`docs/phi-iit-results.md` 里的 EMD 版自实现给出 0.008 vs 零模型 0.003（"弱阳性"）；
PyPhi 给出的是"与零模型不可区分"。两个实现细节不同（我的版本只做系统级二分割，
PyPhi 做完整的机制/概念/MIP），**结论以 PyPhi 为准：不可约性没有证据。**

## 5. 局限

1. **state-by-node TPM 由转移计数估计**，同一时刻的节点相关被丢掉
2. 只有 3 个元素（temporal 的显著度是常数，被剔除）；`Φ` 在这么小的系统上本来就难稳定
3. 按 3 个状态平均是为了省时间，不是 IIT 的标准做法（标准是对给定状态算）
4. PyPhi 1.2 需要打兼容补丁才能跑在 3.12 上——换机器要重装，`evidence/phi_pyphi.json` 记录了版本

## 6. 对判定的影响

`docs/strong-candidate-verdict.md` 的"不可约性"恢复为 **❌**，但理由升级为：
**参考实现（PyPhi / IIT 3.0）算出的 Φ 与打乱零模型不可区分，且估计不稳定。**

这比"我们的代理量 ≈ 0"硬得多：现在用的是同行评审论文配套的参考实现，
而且校准过（独立 0 / 耦合 0.25）。
